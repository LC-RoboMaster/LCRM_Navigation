# rmuc_2025 通道仿真

运行地图为 `rmuc_2025.yaml` + `rmuc_2025.pgm`，编辑工程为 `rmuc2025.json`，导航通道文件为 `rmuc_2025.passages.json`。工程和通道文件均使用 YAML 的世界原点 `[-3.58,-9.44,0]`，不是图片左下角原点 `(0,0)`。工程测试半径 0.2 m、安全边距 0.02 m，与当前仿真 Nav2 一致；独立试规划仍不包含实时点云。

编辑后请重新“导出导航通道文件”覆盖 `rmuc_2025.passages.json`，再编译/安装 bringup 或使用指向源码 JSON 的绝对路径参数。只保存工程不会更新自动加载的导航文件。编辑工程保留四处原始标注的区域和方向；A/B 按当前测试半径重新自动对齐。示例对已确认门梁投影显式开启 `clear_unknown`，处理 trinary 图片中门梁边缘的静态未知。

第一处测试的起点约为 `(6.55,-4.60)`，终点约为 `(9.67,-3.36)`；第二处约为 `(12.63,0.61)` 到 `(15.73,2.06)`。这些点位于通道区域外。固定边仍会被中线上的实时障碍否决，配置中的通道不保证每条目标路线都经过它。

第三、四处原始标注附近有较紧的墙体与转角，当前普通半径下入口/出口连接可能无效。请在 RViz 的 Passage Planner Diagnostics 中观察具体拒绝原因，再按真实门洞位置调整矩形长轴、A/B 和释放距离；不能仅通过加载数量判断这些方向都可用，也不要把相邻墙体一起擦除。可用未选中为黄色，已选中绿色，拒绝红色。

脚本 `bash rm_navigation_bringup_sim.sh` 默认启用仿真机构反馈；直接使用 launch 时需要自行传 `simulate_deformation:=true` 才会模拟完成确认。这只模拟控制接口，不会修改 Gazebo 模型形状。
