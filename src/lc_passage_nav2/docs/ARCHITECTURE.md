# 架构与执行约定

## 数据流

`map -> PassageMapNode -> passage_map -> global/local static_layer`

`terrain_analysis -> terrain_map -> PassageMapNode -> terrain_map_nav -> intensity_voxel_layer`

`global costmap -> TdtPassagePlanner -> Path + PassagePlan -> OmniPidPursuitController -> velocity_smoother -> FakeVelTransform -> cmd_vel`

原始三维点云、里程计、SLAM 扫描、原始地图和重定位输入不被通道处理修改。矩形擦除只作用于静态 OccupancyGrid：默认仅清已知占据，显式设置通道 `clear_unknown=true` 时也清除该矩形内的静态未知；区域外未知保留。实时点云只在已标注矩形且相对地面高度属于门梁区间时过滤。不会在合并后的 costmap 擦除区域，低矮障碍和中线真实障碍仍有效。

## 全局规划

每次规划短时间持有 costmap mutex 复制栅格，随后释放锁再计算。254 表示物理障碍，255 按未知策略处理，253 及以下保留为软代价；普通区由核心按圆形半径和安全边距膨胀一次。SLAM 扩图不要求编辑工程图片与实时栅格同尺寸。

特殊矩形是对机器人中心的路线约束，先对真实占据做半径膨胀，再屏蔽特殊矩形，避免把语义边界当实体墙额外膨胀并封住 A/B。地图处理、独立 CLI、Nav2 插件使用一致的显式静态未知清理规则；插件自身始终关闭清理，防止擦掉 master costmap 中的实时障碍或未知。

`PassageMapNode` 发布可靠且 transient_local 的 `passage/markers`，显示配置几何，并根据 `passage/active_plan` 与 `passage/state` 绘制实际采用路径上的事件和状态。规划器在成功和失败时都发布 `passage/planner_diagnostics` 与 `passage/planner_markers`，保留每个方向的可用性、拒绝位置、是否选中和路线代价。可视化不会反馈修改地图或执行状态。

普通搜索禁止穿越已声明的特殊矩形，通道 A/B 与外部释放点构成有向图边；双向通道自动交换入口与出口。图搜索可选择绕行、多个通道、连续通道；未选中的通道不产生执行事件。选中普通段可由 TDT 后端优化；通道 A 到 B 再到释放点始终保留直线，不经过 Nav2 后置平滑。

入口 A/B 在矩形外，并严格位于长轴中线。入口和释放点必须与普通自由空间连接。通道端点本身不会被当作障碍单元或附带机械尺寸可行性测试；固定中线仍检查实际占据与未知。起点或终点落在特殊区域内不接受新规划：执行时通过已提交路径锁定处理，而非在洞内重新寻找入口。

## 路径采用与重规划

规划器的 `passage/plan` 是候选，不能触发变形。PID 控制器收到 `setPlan` 后逐点匹配候选的坐标、朝向与 frame，再采用同一份弧长标记并发布 `passage/active_plan`。元数据乱序时停车等待，超过 1 秒不再豁免进度检查。支持 Nav2 `ComputePathThroughPoses` 的逐段路径拼接；拼接段的弧长和标记随前段长度平移。

状态机保存完整原始路径；原控制器对局部路径的裁剪不会影响标记。进度通过局部弧长窗口投影并保持单调，避免路径折返或定位跳变直接跳到出口。变形请求发出后，控制器拒绝换路；BT 暂停重规划，规划器也可返回已提交路径。释放后恢复正常重规划。普通任务切换在 `lc_robot_cmd` 中延迟至释放；外部取消和急停仍可停车。

## 控制状态

| 状态 | 动作 |
| --- | --- |
| NORMAL | 普通 PID 跟踪 |
| APPROACH | 前视点不越过准备点，按制动距离限速并停稳 |
| WAIT_FOLD | 请求 folded，停车，等待对应 request_id/mode 的完成反馈及停留时间 |
| PASSING | 保持变形，短前视跟踪中线，通道限速，禁止自旋 |
| WAIT_RESTORE | 在释放点停稳，请求 normal，等待确认与停留 |
| FAULT | 停车，保持当前机械状态和路径锁，不自动恢复 |

相邻通道的准备/释放窗口相交时合并保持 folded，只在整组最后的释放点恢复。反馈超时、硬件故障、时钟倒退或锁定状态下大幅偏离路径会锁存故障。动作与停留均不阻塞控制线程；计时使用单调时钟。

通道等待由专用 ProgressChecker 豁免常规“不移动”超时，但动作本身受 `passage_action_timeout` 限制。真正遇障碍停车不豁免普通进度检查。GoalChecker 必须等释放与恢复完成才允许结束目标。BT 的 `PassageSafeRecovery` 在锁定时阻止清图、倒退等恢复操作。

最终速度门位于平滑器之后。等待、故障或锁定状态的心跳超时会持续输出零速度；锁定时不会叠加原有陀螺速度。中线外仍使用普通膨胀碰撞检查，中线上使用实际占据检查。

## 生命周期和故障恢复

取消导航/停用控制器只停车并保持变形，不会因取消而展开。控制器计算暂停时仍发布保持停车的状态。重新规划不能清除故障。发生机械故障后应人工停车、在洞外恢复机构并重新启动导航，再发送新目标；不能在洞中靠重启清锁继续行驶。

配置仅在启动/生命周期配置时读取，不支持运行中编辑覆盖。当前只实现 folded/normal 两种机械模式。算法不估计可穿过的真实尺寸，也没有实现原始点云在线识门或自动生成通道。
